## Why
The 1.0 checks passed, but turned up small rough edges: one stale view, two keyboard and focus gaps, inconsistent
wording, a defense-in-depth gap, an outdated web README and a flaky test. None blocks use, and fixing them before the UI
refresh (F-002) means the redesign starts from a correct baseline. This is also the first feature run end to end with v2.

## User stories
### Web
- **F006-W1**: As a user, every screen reflects a delete or restore immediately, without a reload.
  Known cases: Home "Recently updated" keeps items of a deleted folder (C4), and the Trash page doesn't show something
  trashed elsewhere (sidebar, item view) while it's open (user report). Root cause seen by the top-level orchestrator:
  `trashKeys` is only used in `features/trash/api.ts`, so the delete mutations in `features/items/api.ts` and
  `features/tree/mutations.ts` never invalidate the trash list or `homeKeys.recent`.
  Acceptance: one shared "content changed" invalidation used by **every** mutation that trashes, restores, purges, moves or
  creates (tree, lists, items, trash, search, Home recent, Trash list), instead of per-feature lists. Tests: trash an item
  and a folder while the Trash page is open → they appear; delete a folder → Home drops its items; restore → they come back.
- **F006-W2**: As a keyboard user, I can reach the sidebar tree with Tab alone, and move inside it with the arrow keys.
  Acceptance: first confirm the C4 suspicion. If it's real, one Tab stop enters the tree (roving tabindex), with a test. If not, record "not reproducible" (C4).
- **F006-W3**: As a keyboard user, when I close "Add item" with Esc, focus returns to the button that opened it.
  Acceptance: the same holds for every dialog opened from a button (check the shared Dialog primitive first); a test (C4).
- **F006-W4**: As a user, the delete confirmation and the Trash entry report the same counts for the same deletion.
  Acceptance: one rule (does the root folder count?) applied in both places, with wording aligned (C4). If the server's
  counts are the source of the mismatch, raise it as a backend story instead of patching the client (AGENT_WORKFLOW §6).
- **F006-W5**: As the owner, the IMDb link is only rendered for an `https://(www.|m.)imdb.com/title/tt…` URL, even if bad data
  slips into the database. Acceptance: client-side check mirroring the backend pattern, with a test (Q-05 finding 6, low).
- **F006-W6**: As a new maintainer, `frontend-web/README.md` describes the app as it is today (features, layout, `./deploy/dev|test`,
  `npm run check` needs Docker and runs `api:check`, troubleshooting). Acceptance: every gap listed in handoffs/Q-04.md "Questions" is fixed.
- **F006-W7**: As a developer, the `ItemEditForm` AT-05 test is stable under load. Acceptance: 20 consecutive `npm test` runs with
  no failure in that file, or a written reason why it can't be fixed (Q-04 finding).
- **F006-W9**: As a user, I don't see a "Backend: ready" indicator in the shell. The app stays environment-agnostic,
  and the connection details live in **Settings**. Acceptance:
  - `BackendStatus` is removed from `layouts/AppShell.tsx` and `layouts/Sidebar.tsx`
  - Settings gets a "Connection" (or "About") section showing: backend status (ready / unreachable, via `/readyz`, with a
    "Check again" button); the **API address the app uses**, i.e. `<window origin>/api` (D-033/D-016: the browser always calls
    the same origin, and dev, test and prod proxies forward it); and the **API contract version** the client was built for
    (`api/openapi.lock.json` tag, e.g. `api-v0.2.0`), plus the app version if it's cheap to get at build time
  - The backend's internal address (container IP or port behind the proxy) is **not** shown: the browser can't know it, and
    exposing it would need a new endpoint that leaks topology. If you want it anyway, it becomes a backend story (contract change)
  - Update the web README/troubleshooting text that mentions the header indicator (with W6)
- **F006-W8**: As the owner, the production image's CSP is verified in a real browser. Acceptance: `./deploy/prod` (or a trial
  project) loaded in the browser pane shows 0 CSP violations across Home, a list, an item with an image and Markdown, Settings
  and Trash (Q-05 finding 8, not verified live).
