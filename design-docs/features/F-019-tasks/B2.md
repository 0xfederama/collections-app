## T4 · Explicit purge (no cascade needed)
In `internal/trash/trash.go` (`purgeBatch`) and `db/queries/trash.sql` replace "delete the root, let FKs cascade" by explicit steps inside the existing tx, in this order, using plain queries (no CTE): collect ids in Go, then `DELETE ... WHERE id = ANY(@ids)`:
1. folders: `ListFolderParents :many` (id, parent_folder_id of ALL folders of the workspace, any state); compute in Go the subtree of the root (cycle-safe, visited set).
2. lists: `ListListIDsByFolders :many` (folder_id = ANY(@ids)) plus the root list for a list batch; 3. items: `ListItemIDsByLists :many`, plus the root item for an item batch.
4. attachments to purge: `ListAttachmentKeysByItems :many` (replaces the recursive `PurgeAttachments`) → file keys returned as today.
5. delete in order: `DeleteContentVersionsOfItems`, `DeleteLookupImportsOfItems`, `DeleteItems`, `DeleteLists`, `DeleteFolders` (one statement for all folders: parent FK is checked at statement end), then the attachment rows, then the batch rows (existing logic).
Remove queries that become unused (`PurgeFolder`, `PurgeList`, `PurgeItem`, the recursive `PurgeAttachments`) after grep. Behaviour, error mapping and the files-after-commit rule do not change.
Must pass: T3 tests and the whole existing `internal/httpapi` trash tests (`go test ./internal/httpapi/ -run 'Trash|AT11|AT12|AT13|AT14|Purge|B2'`) plus `go vet ./...`. FLAG as [CRUCIAL]: ordering, tree lock still taken, files deleted after commit.
