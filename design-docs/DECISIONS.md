(3) **Locking:** create, move and reorder of items take D-060's per-workspace tree lock; PATCH takes only the item row lock (`FOR UPDATE`). Trash delete of an item (B-10) must take the tree lock too. (4) **Edge rules:** move errors are 404, 412, then 409 `destination_unavailable`; moving into the same list re-appends at `max+1` (the old slot is not reused) and bumps the version; reorder of a trashed or missing list is 404; `list_id` missing from a move body is 422; a PATCH whose result equals the stored row answers 200 with no bump (D-059); `summary` and `status` are trimmed like names. (5) **Lists:** the default `sort` is the list's `sort_mode`; `q` is escaped in Go (`\`, `%`, `_`) and matched with `lower(title) LIKE … ESCAPE '\'`; `total` is a separate `count(*)` so it is right past the last page. | The price rules of D-015 needed an exact mapping; replace-not-merge keeps metadata equal to what the client sent and avoids ambiguity about clearing keys; one tree lock is already how structural writes are serialized | `float64`/`decimal` library for prices; merge-patch for metadata; per-list advisory locks |
