## Goal
`/lists/:listId` shows the list's items in its display mode, with sort, title filter, item drag-reorder in manual sort, and
fallback tiles for missing images, with loading/empty/error states and back-navigation that restores scroll.

## Scope
1. **Hooks** in `src/features/lists/api.ts`: list detail (`GET /lists/{id}`) and items (`GET /lists/{id}/items` with sort, q,
   limit 200, offset; "Load more" beyond 200), list PATCH (`display_mode`, and `sort_mode` if item 3 says so) with `ifMatch`,
   items reorder. Export query keys (W-05 invalidates them).
2. **Header:** name, description (expandable), item count, **Add item** button (opens nothing yet or a stub: the create-item dialog
   is W-07/W-08 scope; ask if unsure), display mode SegmentedControl (icons with accessible labels; changing it PATCHes the list,
   on 412 refetch and retry is **not** automatic: refetch and toast), sort Select, filter field (debounced, `?q=` in the URL).
3. **Sort semantics (decide with the user, not clear-cut):** UI_SPEC §1 says the sort *override* is URL state, while the list also
   persists a `sort_mode`. Recommendation to propose: the select writes `?sort=` (override, default = list `sort_mode`), plus a
   "Make this the default sort" action that PATCHes `sort_mode`. Record the answer as a D-entry.
4. **Modes** (UI_SPEC §3): compact rows, thumbnail rows, grid cards (2 / 3 / 3–4 / auto-fill min 220px per §2). Status chip with
   text, price via `Intl.NumberFormat` (single or range), kind icon/badge from `icons.ts`. Rows link to
   `/lists/:listId/items/:itemId` (the shell decides panel vs full page).
5. **Fallback tile:** tinted tile with the kind icon and the title's first letter; external image load errors fall back to it; no
   broken-image glyph. `alt` = item title; decorative tile has empty alt.
6. **Drag-reorder** with `@dnd-kit/react` (D-061) behind our own wrapper component: handles only in manual sort with no filter and
   all items loaded (otherwise hidden, with a hint why). Optimistic with rollback; `409 order_stale` → refetch + toast "List changed,
   order refreshed."; keyboard dragging, live-region announcements, "Move up/down" menu fallback.
7. **Back navigation:** below 1280 the list unmounts while an item is open; restore the list scroll position and filter when
   returning (UI_SPEC §1).
8. **States:** skeletons per mode, empty list (EmptyState + Add item), empty filter result, error + Retry.
9. **Dev mocks:** `src/mocks/devItems.ts` with a few items per dev list covering every kind, with and without images, so all modes
   and the fallback tile show; reorder and PATCH work in memory.
10. **Tests** (test-writer; you run and review): each mode renders, sort/filter URL state, price formatting, fallback tile on error,
    reorder (keyboard) + order_stale rollback, handles hidden with a filter, display mode PATCH sends `If-Match`, scroll restore.
11. **Docs:** CLAUDE.md as needed; docs-keeper adds `docs/modules/lists.md`.
