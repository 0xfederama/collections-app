## Goal
`/trash` lists deleted batches and lets the user restore them (in place or to a chosen destination) and purge them, with the
blocked-parent flow and confirmations of UI_SPEC §7 and PRODUCT §10 (AT-11 web side).

## Scope
1. **Hooks** `src/features/trash/api.ts`: trash list (paginated, "Load more"), restore (with or without destination), purge;
   exported `trashKeys`. The trash query must be fresh on every visit (`staleTime: 0` / refetch on mount), because the delete
   actions in W-05/W-07 don't know about it (don't edit them). After restore or purge invalidate tree, list detail/items, item and
   search queries (by their exported keys).
2. **Page:** one row per batch with kind/type icon, name, type, former path, relative deleted time (absolute on hover/title), counts
   ("3 lists, 41 items"; counts include the root, D-065). Loading skeletons, empty state ("Trash is empty"), error + Retry.
   Responsive: table-like at ≥ 768, stacked cards below.
3. **Restore:** in place when `restorable_in_place`; success toast with a link to the restored thing (from `{ root_type, root_id }`).
   Otherwise the button is **"Restore to…"** with the reason (e.g. *Parent folder 'Bikes' is in Trash*), offering **"Restore 'Bikes'
   instead"** when the blocking parent is the root of a trash entry (find it from the loaded entries; if it can't be determined,
   don't guess: only offer the picker) and the destination picker: folders (or root) for folder/list roots, lists for item roots;
   invalid destinations disabled with a reason.
   Handle the race where the server answers `409 parent_in_trash` anyway: refresh the entry and switch to "Restore to…".
4. **Purge:** "Delete permanently" AlertDialog stating counts, that image files are deleted, and that nested older trashed entries
   are included (PRODUCT §10). No type-to-confirm. Success toast; row removed.
5. **Errors (UI_SPEC §9):** 404 (already restored/purged elsewhere) → toast + refetch; 409 `cycle_detected` /
   `destination_unavailable` → message in the picker, keep it open; network/5xx → inline error + Retry.
6. **Dev mocks:** `src/mocks/devTrash.ts`: a stateful trash with a few batches (folder with contents, list, item, one with
   `restorable_in_place: false`), restore/purge removing entries, problem shapes from `src/mocks/problems.ts`. It doesn't need to
   sync with the dev tree/items (they're W-08's); say so in docs.
7. **Tests** (test-writer; you run and review): AT-11 web side: list rendering and counts, restore in place, blocked → Restore to…
   and Restore parent instead, destination picker validity, 409 race, purge confirmation text, 404 refetch, invalidations.
8. **Docs:** CLAUDE.md as needed; docs-keeper adds `docs/modules/trash.md`.
