## Goal
From the sidebar the user can create, rename, move and delete folders and lists, and reorder siblings by drag (pointer and
keyboard), with the conflict and error rules of UI_SPEC §9. The same actions are exported for the list header (W-06).

## Scope
1. **Mutation hooks** in `src/features/tree/` (TanStack Query): create/rename/delete/move for folders and lists, list description
   edit, folder and list reorder. Writes use `ifMatch(...)` from the resource's `version`; no auto-retry on 412. Invalidate the
   exported tree query key (and the list query W-06 uses, via its exported key once it exists; until then the tree key).
2. **"+" menu** (`TreeHeaderActions`): New folder / New list at the root. **Row context menu** (`TreeRowActions`): folder → New
   folder inside, New list inside, Rename, Move, Delete; list → Rename, Edit description, Move, Delete. `TreeEmptyAction` creates the
   first list. Menus are keyboard reachable from the row (e.g. a row "More" IconButton, Shift+F10 / ContextMenu key if cheap).
3. **Dialogs** (UI_SPEC §5): name dialog (create and rename, parent preselected from context), description dialog, delete
   AlertDialog (says the contents go to Trash), **move dialog** with a tree picker where invalid destinations (self, descendants,
   current parent) are disabled with a reason tooltip. After create, navigate to the new list.
4. **Errors (UI_SPEC §9):** 412 keeps the dialog open with its value and offers Reload latest (no auto-merge); 409
   `destination_unavailable` / `cycle_detected` show a clear message and refresh the tree; 422 maps to the field; network/5xx keep
   the value with Retry. Toasts for success.
5. **Drag-reorder** with `@dnd-kit/react` (D-061) wrapped in our own component so the library stays behind one seam: reorder
   **siblings of the same type within the same parent** only (folders among folders, lists among lists). Moving across parents is the
   Move dialog, not drag (keeps scope sane; say so in the PR). Optimistic update with rollback on failure, `409 order_stale` → refetch
   + toast "List changed, order refreshed." Keyboard dragging and live-region announcements required (UI_SPEC §12). "Move up/down"
   menu entries as the fallback.
6. **Tree focus fix:** clicking a row's inner link moves the roving focus to that row (W-04 note).
7. **Export for W-06:** `src/features/tree/ListActionsMenu.tsx` (`<ListActionsMenu list={list} />`: rename, edit description, move,
   delete; after delete navigate home). Whichever of W-05/W-06 merges **second** wires it into the list header (a few lines in
   `ListRoute`/`features/lists`, the one exception to ownership).
8. **Dev mocks:** `src/mocks/devTree.ts` keeps an in-memory tree so create/rename/move/delete/reorder work with
   `VITE_API_MOCKS=1`, returning the same problem shapes as the spec (`src/mocks/problems.ts`).
9. **Tests** (test-writer; you run and review): AT-03/AT-04/AT-21 web side: create nested, rename, move with disabled invalid
   destinations, delete, reorder (keyboard), order_stale rollback, 412 keeps the draft, 409 messages, payloads always include the
   parent field.
10. **Docs:** CLAUDE.md (dnd seam, ownership note removed after merge if stale), docs-keeper updates `docs/modules/tree.md`.
