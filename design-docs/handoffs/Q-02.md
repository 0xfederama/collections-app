## Scope
- **backup.sh [dest]** (default `./backups`, gitignored): stop `api` (trap restarts it on any exit), `pg_dump -Fc` via the `db` container →
  `<ts>/db.dump`, tar of the images dir → `<ts>/files.tar.zst` (if `zstd` isn't available in the containers/host, pick a fallback and record
  it in DECISIONS), `manifest.json`: timestamp, migration version (`schema_migrations`), app version (git describe or image label), sha256
  of both files, **row counts per table**, and per item the sha256 of the latest content body (what verify needs). No secrets in the manifest.
- **restore.sh <backup-dir> [--force]**: refuse non-empty target volumes unless `--force` (which prompts); verify manifest hashes first;
  restore into a fresh DB, extract files, run `migrate up` (compose `migrate` service), start `api`.
- **verify-restore.sh <backup-dir>**: compare counts per table with the manifest; every attachment's original and thumbnail exist and the
  original's sha256 matches `attachments.sha256`; every item's latest content body sha256 matches the manifest. Non-zero exit with a clear
  report on any mismatch.
- Scripts: `set -euo pipefail`, shellcheck-clean (run shellcheck via its pinned Docker image in `make check`, or explain why not), work with
  the compose project from any cwd, never print the DB password, never `user:pass@` URLs (GitGuardian).
- **AT-17 test** `make test-backup` (separate target; probably too slow for every `make check`: measure and decide, record in DECISIONS):
  isolated compose project (own name, own volumes, ports not clashing with dev), seed through the **API** (folders, lists, items with uploaded
  images, several content versions, something in trash), backup → wipe volumes → restore → verify-restore passes; then corrupt one file
  and check verify fails. Tear down always.
- README: backup/restore section (incl. "back up before every migration in production", retention advice from §4). CLAUDE.md: commands.
