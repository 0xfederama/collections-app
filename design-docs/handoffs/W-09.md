## Goal
In edit mode the user sets, replaces or removes the item image by drop, file picker or URL, with client-side checks, upload
progress and its own success/error toast; the change is its own request, applied immediately (UI_SPEC §4).

## Scope
1. **Dropzone** "Drop an image or **browse**" (keyboard reachable button, `accept="image/jpeg,image/png,image/webp"`), drag-over
   state, paste is optional. Client checks: type and ≤ 10 MiB with clear messages; the server stays authoritative (map its codes to
   messages: wrong type, too large, too many pixels, unreachable URL…).
2. **Upload** `PUT /items/{id}/image` multipart (field `file`) with `If-Match` from the current item version and a **progress bar**
   (XHR upload progress if fetch can't; keep it inside one small helper and say why in the PR). Cancel while uploading.
3. **"Use image URL"**: text field (`https://` only client-side), JSON PUT. **Remove image**: DELETE with confirmation-free undo-less
   action plus toast (it's reversible by re-uploading; ask if you disagree).
4. **Version snapshot (W-08 note):** image requests return the Item with a new `version`. Update the item cache **and the edit
   form's base version** so the next Basics save doesn't 412, without touching the user's other draft fields. A real 412 on the image
   request follows UI_SPEC §9 (message + Reload latest; never lose the Basics draft).
5. **View mode:** `ItemHero` shows thumbnail/original correctly (lightbox uses the original), keeps the fallback tile on error.
   List view thumbnails come from the list query: invalidate list items/detail after a change.
6. **Dev mocks:** `devImages.ts` accepts uploads/URLs in memory (object URLs or a placeholder image), returns new versions, rejects
   wrong types/sizes with the spec's problems.
7. **Tests** (test-writer; you run and review): type/size checks, progress reporting, cancel, URL path, remove, version snapshot
   (image change then Basics save sends the new `If-Match`), 412 on image keeps the draft, server error codes → messages.
8. **Docs:** CLAUDE.md, docs-keeper updates `docs/modules/items.md`.
