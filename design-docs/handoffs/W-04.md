## Goal
The app has its real frame: a responsive shell (drawer / rail / resizable sidebar / detail panel) with the folder/list tree loaded
from `GET /api/v1/tree`, expand state persisted, breadcrumbs, and every UI_SPEC §1 route registered with a placeholder. After this
PR, W-05 (tree actions and CRUD dialogs) and W-06 (list view) can run **in parallel** without touching the same files, so the
seams in item 6 matter as much as the visuals.

## Scope
1. **Data hooks.** `src/features/tree/api.ts`: `useTree()` on `GET /api/v1/tree`, plus a pure `buildTree(folders, lists)`
   (nesting by `parent_folder_id` / `folder_id`; per parent: sub-folders first, then lists, each by `(sort_order, id)`, UI_SPEC §2)
   and lookups the breadcrumbs need (ancestors of a folder or list). `src/features/settings/api.ts`: `useSettings()` for the
   workspace name only (W-13 extends it). Query keys exported as constants so W-05/W-06 invalidate them, not string literals.
2. **Shell layout** (`src/layouts/`), with landmarks `nav` (sidebar), `main`, `aside` (detail panel):
   - < 768: top bar with a menu IconButton opening the sidebar in the `Drawer` primitive; closes on navigation.
   - 768–1023: collapsible sidebar, icon rail ↔ full, toggle persisted.
   - ≥ 1024: persistent sidebar, 280px default, resizable 220–400 with pointer **and** keyboard (a focusable separator with
     `role="separator"`, `aria-valuenow/min/max`, arrow keys), width persisted.
   - ≥ 1280: a detail-panel region (min 420px) beside `main`, shown only when the item route is active; below 1280 the item
     route renders full page in `main`. Content is a placeholder (W-07). Build it so W-07 only swaps the component.
   - Breakpoints from UI_SPEC §2 in one place (CSS or a small `useMediaQuery`, your call; tested).
   - The backend-status indicator from W-02 stays visible somewhere unobtrusive.
3. **Sidebar contents** in order: workspace name, global search field (`/` focuses it unless typing in a field; Enter navigates
   to `/search?q=`), the tree, then Trash and Settings links at the bottom. Loading = Skeleton rows; error = message + Retry;
   empty = EmptyState that says how to start (the create action itself is W-05: leave a slot).
4. **Tree.** Use the `Tree` primitive: folders expand/collapse, lists are links to `/lists/:listId` with `item_count`, the active
   list is `aria-selected` and its ancestors auto-expand. Expanded folder ids persist in `localStorage` (ignore ids that no
   longer exist).
5. **Routes and breadcrumbs.** Register all UI_SPEC §1 routes under the shell, each its own file in `src/routes/` with a minimal
   placeholder: `ListRoute` (`/lists/:listId`, with a nested `items/:itemId` → `ItemRoute`), `SearchRoute`, `TrashRoute`,
   `SettingsRoute`. Unknown list id (not in the tree) → not-found state, not a crash. Breadcrumbs (folder path › list › item
   placeholder) above `main` content, from the tree data.
6. **Seams for W-05 ∥ W-06** (record them in the PR and in `docs/modules/shell.md`):
   - W-05 will add the "+" menu, per-row context menu (rename/move/delete) and drag-reorder to the tree. Give the tree row a
     render prop or slot (e.g. `renderRowActions`, a header actions slot, an empty-state action slot) so W-05 works in
     `src/features/tree/*` only and never edits `src/layouts/*` or `src/routes/*`.
   - W-06 will build the list view inside `src/routes/ListRoute.tsx` and `src/features/lists/*` only.
   - Shared files after this PR: `src/app/router.tsx` (both may need to touch it: avoid it by registering everything now).
7. **localStorage keys** prefixed `collection:` like the theme key (e.g. `collection:tree-expanded`, `collection:sidebar`);
   read in try/catch, tolerate garbage.
8. **MSW.** The default Tree example must give a useful dev tree (nested folders, a few lists, a root list). If the spec example
   is too thin, override it in `src/mocks/` (not the spec), keeping it valid against the generated types. Ask before changing
   anything about how mocks are built.
9. **Tests** (test-writer writes; you run and review): `buildTree` ordering and nesting, expand persistence and stale ids, tree
   keyboard + navigation to a list, active-list ancestors expanded, drawer opens/closes at mobile width, rail toggle, resize via
   keyboard with clamping, `/` shortcut, breadcrumbs, item route full-page vs panel, loading/error/empty states, unknown list.
10. **Docs.** CLAUDE.md: layout seams, storage keys, breakpoint helper. docs-keeper: `docs/modules/shell.md`, `docs/modules/tree.md`.
