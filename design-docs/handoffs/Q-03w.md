## Contract with Q-03 (D-069)
- The image listens on **`:8080`** inside the container, serves the SPA with **history fallback** (`/lists/…` deep links reload
  fine), and reverse-proxies **`/api/*`** and **`/readyz`** to **`api:8080`** (upstream overridable by env var, default
  `api:8080`, so the same image works in other compose setups). Same origin, no CORS (D-033).
- Runs as a **non-root** user, read-only friendly (Caddy's data/config dirs writable via env or tmp), no published ports of its own
  (Q-03 decides `127.0.0.1:${WEB_PORT:-8081}:8080`). Provide a cheap health endpoint or document the healthcheck command Q-03 should
  use (e.g. `wget -qO- http://127.0.0.1:8080/` or a static `/healthz` answered by Caddy; don't proxy the healthcheck to the API).
- No auto-HTTPS inside the container (`auto_https off` / `:8080` site), no admin API exposed (`admin off` or localhost).

## Scope
1. **Dockerfile**, multi-stage: `node:24-alpine` (pin the exact tag/digest you verify) → `npm ci` → `npm run build` (note
   `vite.config.ts`'s plugin already drops `mockServiceWorker.js`; verify it's not in the image) → `caddy:2.11.7-alpine` (R-1)
   with `dist/` and the Caddyfile. Builds natively on arm64 and amd64 (no arch-specific steps). Small final image; report its size.
   `.dockerignore` excludes `node_modules`, `.git`, `dist`, test output, `.env*`.
2. **Caddyfile:**
   - `encode zstd gzip`; `try_files {path} /index.html` for the SPA, but **not** for `/api/*`, `/readyz` or missing hashed assets
     (a missing `/assets/x.js` must 404, not return index.html).
   - Caching: `/assets/*` (hashed) `Cache-Control: public, max-age=31536000, immutable`; `index.html` `no-cache`; fonts/favicon sensible.
   - Security headers: `Content-Security-Policy` per ARCHITECTURE §5 — `default-src 'self'; script-src 'self' 'sha256-…'` (the
     **inline no-flash theme script hash**, CLAUDE.md gotcha; compute it at build time from the built `index.html` so it can't
     drift), `style-src 'self'` (check whether Radix/React inject inline styles: if `'unsafe-inline'` for styles is truly needed,
     ask and record why), `img-src 'self' https: data: blob:`, `font-src 'self'`, `connect-src 'self'`, `object-src 'none'`,
     `base-uri 'self'`, `frame-ancestors 'none'`, `form-action 'self'`; plus `X-Content-Type-Options: nosniff`,
     `Referrer-Policy: strict-origin-when-cross-origin` (or `no-referrer`; images already send none), `Permissions-Policy` minimal,
     `Cross-Origin-Opener-Policy: same-origin`. Remove the `Server` header. No HSTS (served over HTTP on a LAN/Tailscale; note it).
   - Proxy headers: pass `X-Request-Id` through untouched; don't strip `ETag`/`If-Match`; request body limits are the API's.
3. **`npm run check`** builds the image (`docker build -t collections-web:check .`) as its last step (D-069). If Docker isn't
   running, fail with a clear message (don't silently skip; ask if you think a skip flag is needed for workers without Docker).
4. **Verification script or documented steps:** run the image against the dev backend (`docker network` or `--add-host`), then
   check: deep-link reload, `/api/v1/tree` proxied, `/readyz` proxied, a missing asset 404s, headers present (curl -I), the app
   works in the browser with **no CSP violations in the console** across Home, list (all 3 modes), item detail with Markdown and an
   external https image, edit form, trash, settings, search, theme switch, `/dev/ui` absent.
5. **Docs:** CLAUDE.md (commands row, CSP-hash gotcha updated, "check needs Docker"), docs-keeper adds `docs/modules/deploy.md`
   (how the image is built and what Q-03 relies on).
