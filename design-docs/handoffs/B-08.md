## Scope
- Service `internal/content`, queries `db/queries/content.sql`.
- **GET content**: highest version or `{version: 0, body: ""}`; `ETag: "c-N"`. Trashed/missing item → 404.
- **PUT content** `{ body }` with `If-Match: "c-N"`: body ≤ 1 MiB **UTF-8 bytes** (valid UTF-8 required → 422 otherwise; > 1 MiB → 413
  `payload_too_large`, even if the JSON body fit under 2 MiB). In one tx: lock the item row `FOR NO KEY UPDATE`, read latest (version +
  sha256), mismatch → 412 with `current_version`; equal sha256 → 200 with the same version (no insert); else insert `current+1`, prune
  `version <= new - (limit + 1)` using the workspace's `markdown_history_limit`, bump `items.updated_at` but **not** `items.version`.
- **Versions list**: `{ data: [{version, size_bytes, created_at}] }` newest first. **Version GET**: that version's Content + its ETag; a
  pruned or unknown version → 404.
- **Restore** `{ version }` with `If-Match` (current): same as save with the old body (identical to latest → 200 unchanged); pruned → 404.
- `limit = 0` keeps only the latest version. Lowering the limit prunes on the next save per item, not immediately (API.md §5 Settings).
