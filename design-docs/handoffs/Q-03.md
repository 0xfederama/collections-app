## Goal
A home server (Raspberry Pi arm64 or Linux amd64) runs the whole app from a clone of the parent repo:
`docker compose -f deploy/compose.prod.yaml up -d --build`, same origin through the web (Caddy) container, published on
`127.0.0.1:8081` by default, with documented backup, upgrade and rollback. **D-069:** images are built on the server, no registry.

## Scope
- **`deploy/compose.prod.yaml`** (parent): project name `collections-app-prod`; `db` (same pinned postgres image, host path or named
  volume per §5 `/srv/collection/pgdata`), `migrate` (pinned image, migrations from `backend/db/migrations`, runs once), `api` (build
  `../backend`, `APP_ENV=production`, data at `/srv/collection/data`, no published port), `web` (build `../frontend-web`, the Q-03w
  `Dockerfile`; published `127.0.0.1:${WEB_PORT:-8081}:8080` by default; LAN/Tailscale IP only by explicit opt-in variable),
  healthchecks, `restart: unless-stopped`, non-root, least privilege on host paths (document the UIDs). Secrets from a
  `deploy/.env` (gitignored, `deploy/.env.example` with blank values).
- Host paths vs named volumes: §5 says `/srv/collection/{pgdata,data,backups}`. Use bind mounts if they work cleanly with the container
  UIDs and the backup scripts; otherwise named volumes + a documented `backups` path. Record the choice in DECISIONS.
- **Backups in prod**: `backup.sh` / `restore.sh` / `verify-restore.sh` must work against the prod project (compose file + project name),
  writing to `/srv/collection/backups` by default. Prefer configuration (env such as `COMPOSE_FILE`/`COMPOSE_PROJECT_NAME`, a `--prod`
  flag, or a thin parent wrapper) over forking the scripts. Script changes go in a backend PR; keep `make test-backup` green.
- **Exposure check** (STATUS notes: the AT-18 script only renders the backend compose): extend or wrap it so the prod compose is checked
  too (every published port on `127.0.0.1` unless the opt-in variable is set), runnable from the parent (e.g. `./deploy/check.sh`).
- **README** (parent, new "Deploy on a home server" section or `deploy/README.md`): prerequisites (Docker, git, disk), clone with
  submodules, `.env`, first start, Tailscale advice (never port-forward, no public exposure before Phase 3 auth), backup schedule
  (7 daily + 4 weekly off-device, example cron/systemd timer), **upgrade** (backup → `git pull --recurse-submodules` → `up -d --build`
  → `migrate` → `/readyz`), **rollback** (restore the pre-upgrade backup), restore drill.
- Don't break the local `./app` launcher or the parent `compose.yaml`.
