## Goal
Typing in the sidebar search shows the top 8 results in an accessible dropdown; Enter goes to `/search?q=`, a paginated results
page. Each result shows thumb, title and its path, and opens the item.

## Read first
- design-docs: UI_SPEC §1 (`/search?q=`), §6 (search), §10, §11 (Combobox), §12; API.md `GET /api/v1/search` (`q` 1–200 chars,
  `{ data: [{ item: ItemSummary, path }], page }`); ACCEPTANCE_TESTS AT-12 (backend semantics; web shows what it gets).
- code: `frontend-web/CLAUDE.md`, `src/features/search/*`, `src/routes/SearchRoute.tsx`, `src/features/lists/*` (tile, thumb),
  `src/components/ui/Combobox.tsx`, `src/lib/api/*`, `src/mocks/*`.

## Scope
1. **Hook** `src/features/search/api.ts`: `useSearch(q, { limit, offset })`, disabled for empty/whitespace `q`, `q` trimmed and
   capped at 200 chars, `placeholderData` keeps the previous page while typing; exported query keys.
2. **Dropdown** in `SidebarSearch`: 250 ms debounce, ≥ 1 char, top 8 results, rows with thumb (or fallback tile), title and the
   path as a muted breadcrumb (`Folder › List`). ARIA combobox pattern (reuse the `Combobox` primitive if it fits; otherwise build
   on the same Radix Popover and say why): arrows move, Enter on a row opens the item, Enter with no active row goes to
   `/search?q=`, Esc closes and keeps the text. "No results for …" message, loading state that doesn't flicker, error with Retry.
   The existing `/` shortcut keeps working; drawer mode (< 768) works.
3. **Results page** `/search?q=`: input prefilled from the URL, result rows like the dropdown but larger, `page.total` shown,
   "Load more" (offset) up to the total, empty state, error + Retry, skeletons. Changing the query updates the URL.
4. **Navigation:** a result links to `/lists/:listId/items/:itemId` (list id from the path's last entry or the item; check the
   spec, don't guess). The shell decides panel vs full page.
5. **Dev mocks:** `src/mocks/devSearch.ts` searches the dev items in memory (case-insensitive substring on title, `%`/`_` literal)
   so the dropdown is realistic with `VITE_API_MOCKS=1`.
6. **Tests** (test-writer; you run and review): debounce (fake timers), keyboard path, Enter behaviors, Esc, empty and error
   states, URL sync on the page, load more, query trimming/capping, path rendering.
7. **Docs:** CLAUDE.md as needed; docs-keeper adds `docs/modules/search.md`.
