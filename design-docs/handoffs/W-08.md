## Scope
1. **Create item** (UI_SPEC §5): the list header's "Add item" opens a Dialog with title (required) and kind (Select, default
   generic). POST, then navigate to the new item **in edit mode** (e.g. `?edit=1` or route state; pick one and document it).
   Invalidate list items, list detail and tree (counts).
2. **Edit mode** in the item view ("Edit" button from W-07 becomes live): sections *Basics* (title, kind, summary, status, price
   min/max + currency, official URL) · *Image* (placeholder slot, W-09) · *Kind details* (rendered from `kinds/*.ts`; enums as
   Select, numbers with unit suffix; extend the configs with input metadata if needed, keeping `defineFields` exhaustive) ·
   *Description* (placeholder slot, W-10) · *Organization* (move to list, reusing W-07's move dialog).
3. **Save:** one PATCH with only changed fields, `If-Match` from the loaded `version`; `null` clears a nullable field; metadata sent
   as the full object when any kind field changed (D-062). Pending spinner, disabled while pending; success → toast, back to view
   mode with fresh data. Cancel with unchanged form → view mode; with changes → the discard dialog.
4. **Field rules client-side** (server stays authoritative): title length, price decimals (max 2), min ≤ max, "up to" label when
   only max is set, currency required with a price and defaulting to the settings currency, URL scheme `http(s)` only, kind
   ranges/enums from the configs. Kind change → inline warning "Switching kind clears the <kind> details." only when some are set.
5. **422 mapping:** `errors[].field` → the matching input (incl. `price.*` and `metadata.<key>`), first invalid field focused, a
   summary for errors without a matching input. `400 unknown_field` is a bug: show a generic error and log the field.
6. **412 conflict (AT-09):** stay in edit mode with **all draft values intact**, role=alert banner with the exact UI_SPEC §9 text,
   **Copy my draft** (readable dump of changed fields; Clipboard API, fallback Dialog with read-only selectable textarea, toast),
   **Reload latest** (confirm "Replace your unsaved changes with the latest version?" → load fresh, leave edit mode). No auto-retry.
7. **Network / 5xx:** inline error with Retry, draft kept, never called a conflict.
8. **Unsaved guard (AT-22):** React Router `useBlocker` (navigating to another list/item, back button) plus `beforeunload`, with the
   "Discard changes?" dialog; cancel keeps edits, confirm discards. Not triggered after a successful save.
9. **Tests** (test-writer; you run and review): AT-09 (412 → banner, draft intact, copy with clipboard and fallback, reload asks),
   AT-22 (blocker cancel/confirm), 422 mapping incl. metadata keys and focus, kind change warning and metadata reset, price rules,
   changed-fields-only PATCH with `If-Match`, network error keeps draft, create → edit mode.
10. **Docs:** CLAUDE.md (form conventions, edit-mode URL/state), docs-keeper updates `docs/modules/items.md`.
