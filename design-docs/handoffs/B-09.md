## Scope
- `internal/storage`: `FileStore` interface (Put from reader to a temp file + rename, Open, Delete, Walk) + local impl. Storage keys are
  generated (`images/<2 hex>/<2 hex>/<uuid>.<ext>`, `.thumb.jpg`), never user-derived; reject path traversal defensively anyway.
- `internal/images`: validation by **magic bytes** (JPEG/PNG/WebP only; SVG and anything else → 415), `image.DecodeConfig` dimension cap
  ≤ 40 MP **before** full decode (→ 422 or 413: pick one, record in DECISIONS), size ≤ 10 MiB (→ 413), sha256, thumbnail longest side
  640 px JPEG q≈82 with metadata stripped (re-encoding strips it). **EXIF orientation:** decide (researcher: `evanoberholster/imagemeta`
  vs a tiny own APP1 orientation parser vs documenting the limitation), record in DECISIONS; no unmaintained libs.
- **PUT upload**: validate + write original and thumbnail **before** the tx; in the tx (If-Match `"i-N"` → 412) insert `attachments`, set
  `image_attachment_id`, clear `image_url`, bump `items.version`; **after commit** delete the previous attachment row and files. If the tx
  fails, delete the just-written files (best effort; the sweeper is the safety net). **PUT url** `{url}` (http/https, ≤ 2048, as B-07's
  URL rule): set `image_url`, clear the attachment, bump, remove the old attachment after commit. **DELETE**: clear both, bump, cleanup
  after commit. All return the Item with its new ETag.
- **Serving** `GET /attachments/{id}/file|thumbnail`: `Content-Type` from the DB (thumbnail `image/jpeg`), `X-Content-Type-Options:
  nosniff`, `Content-Disposition: inline`, `Content-Security-Policy: default-src 'none'`, `Cache-Control: private, max-age=31536000,
  immutable`. Attachment of a trashed item: still served (trash keeps files) unless the spec says otherwise; unknown → 404.
- **Sweeper** (startup + every 24 h, injected `Clock`, stops on shutdown): delete files under `images/` with no `attachments` row and
  older than 1 h; delete `attachments` rows not referenced by any item and older than 1 h, plus their files. Retries failed deletions
  naturally on the next run. Log counts, not paths.
