## Problem
W-08 and W-12 both saw existing tests time out under load on `main` (`ItemActions.test.tsx`, `ItemView.test.tsx`, different ones
each run; green alone and on rerun). A flaky `npm run check` wastes every worker's time and will make e2e triage harder.

## Scope
1. Reproduce: run `npm test` repeatedly under load (e.g. 5× in a loop, and with `--pool` / `maxWorkers` variations) and record
   which tests fail and how (timeout in `findBy*`, `waitFor`, user-event, lazy route import…).
2. Fix the cause, not the symptom, where it's cheap: e.g. lazy routes resolved per test (preload the route module in tests),
   unnecessary real timers/debounces, `findBy*` on content behind a lazy import, slow Radix animations. If a global change is the
   right fix (Vitest `testTimeout`, `maxWorkers`), make it in `vite.config.ts` and justify it with numbers.
3. Only test files, `src/test-setup.ts`, `src/test-utils.tsx`, `vite.config.ts` test block. App code only if a real bug shows up
   (ask first). Fix the stale comment in `src/features/tree/breadcrumbs.ts` ("until W-07 supplies a title").
4. Acceptance: `npm run check` green, and `for i in 1 2 3 4 5; do npm test || break; done` green (paste the summary). Report the
   wall-clock time of `npm test` before/after.
