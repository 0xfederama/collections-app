## Step 2 — B-00 backend skeleton (`collections-app-backend` (local folder `backend/`), branch `chore/B-00-skeleton`)
- `go.mod` as `github.com/0xfederama/collections-app-backend`, with Go and tool versions from Step 1.
- `cmd/api/main.go` is wiring only: config → slog → pgx pool → chi router → `http.Server` with read, write, and idle timeouts, a max header size, and graceful shutdown on SIGINT and SIGTERM.
- `internal/config`: env vars from BACKUP_AND_DEPLOYMENT §3 (no `CORS_ALLOWED_ORIGINS`, per D-033), validated at startup with clear errors (fail fast).
- `internal/database`: pool constructor only. `InTx` comes in B-04.
- `internal/httpapi`:
  - router plus `GET /healthz` (liveness) and `GET /readyz`
  - `/readyz` returns 200 only if the DB ping succeeds **and** `DATA_DIR` is writable; otherwise it returns 503 with a terse body that leaks no paths or SQL
  - other middleware comes in B-04
- **Makefile:** `run`, `test`, `lint`, `fmt`, `check`, `audit`, `migrate`, `migration name=…`, `generate`, `reset-dev`
  - `check` = format check, then golangci-lint, then `go test ./...` (needs Docker), then a compose-exposure check
  - The compose-exposure check renders `docker compose config` and fails if any port is published on anything other than `127.0.0.1` (AT-18).
  - `generate` is a documented no-op until B-02/B-03, which wire sqlc and codegen, plus their drift checks, into `check`.
  - `audit` = govulncheck. It's not part of `check`, because it needs the network.
  - `reset-dev` prompts before deleting volumes and refuses when `APP_ENV=production`.
- **Dockerfile:** multi-stage build, a runtime image chosen per Step 1, non-root UID, only the binary in the final image. If the runtime is distroless, the binary needs a `healthcheck` subcommand or flag that calls `/readyz`, so compose can use it.
- **`compose.yaml`** is the **single** local entry point, `docker compose up --build`:
  - `db`: official postgres, `pgdata` volume, `pg_isready` healthcheck, **no published ports**
  - `migrate`: golang-migrate image mounting `./db/migrations`, runs `up` once, depends on `db` being healthy
  - `api`: built locally, `appdata` volume at `/data`, depends on `migrate` completing successfully, healthcheck, `restart: unless-stopped`, published on **`127.0.0.1:${API_PORT:-8080}:8080` only**
  - If Step 1 shows `migrate up` fails on an empty directory, use the simplest working fix and record it as a D-entry. Don't invent a fake schema migration, because 000001 belongs to B-02.
  - Also ship `compose.override.example.yaml`, which publishes `127.0.0.1:5432` for the `make run` host loop. The real `compose.override.yaml` is gitignored.
- `.env.example` with placeholders only. `.gitignore` covers `.env`, `data/`, `compose.override.yaml`, and build output. Add a `.dockerignore`.
- Create the `db/migrations/` and `db/queries/` directories (with `.gitkeep`) and `scripts/`. Don't create domain packages, `sqlc.yaml`, or `api/openapi.yaml` (those are B-02/B-03).
- `README.md` covers prerequisites with versions, the one-command start, stop, logs, health, test and check, migrate, `reset-dev`, the host-run loop, and the troubleshooting list from BACKUP_AND_DEPLOYMENT §1. Leave out the CORS item.
- `CLAUDE.md` from the template with the **real** commands. Remove "CI" wording, note that there is no CI and why (D-031), and add the M0 gotchas you discovered.
- Copy in `.claude/agents/{researcher,test-writer,docs-keeper}.md` and `.github/pull_request_template.md`. In the template, change "CI" to "local check output pasted".
- `docs/README.md` plus `docs/modules/config.md` and `docs/modules/httpapi.md`, written by docs-keeper.
- **Tests** (test-writer, sonnet; you review and **run** them):
  - table-driven config validation
  - `/healthz` returns 200
  - `/readyz` returns 200 against testcontainers Postgres with a `t.TempDir()`, and 503 with the DB down or the dir unwritable
- **Manual verification you run:**
